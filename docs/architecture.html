02 · The agent loop

The LLM decides, the AI SDK carries it out

On its own an LLM can only write text. The AI SDK turns its decisions into real actions by running our TypeScript tool functions and feeding the results back.

LLM

The thinker. Reads the situation and picks the next tool, or writes the final answer.

picks tool →
← gets result

Vercel AI SDK

The manager. Runs the tool, passes back the output, loops until done. An open-source npm package, separate from Vercel hosting.

calls →
← returns

Our tools

Plain TypeScript functions that read and write Supabase through Prisma.

LLM "Failures look high. Check txn TXN8812."
SDK runs checkTxnStatus("TXN8812") → { status: "FAILED", bank: "HDFC", errorCode: "U30" }
LLM "Find similar failures in the last 30 minutes."
SDK runs clusterCases({ bank: "HDFC", errorCode: "U30" }) → 38 txns, ₹1,42,300 stuck
LLM "Create an incident and draft a Hindi alert for the 38 users."
SDK runs createIncident(…) and draftCustomerMsg(…) → waits for Approve

05 · Data model (first draft)

Tables in Supabase Postgres

Defined in prisma/schema.prisma. Mock data only. Phone and account numbers are masked in the UI.

PaymentEvent

Every UPI, refund or settlement attempt.

  • txnId, userIdstring
  • typeUPI · REFUND · SETTLEMENT
  • bank, amountstring, int
  • status, errorCodestring
  • createdAtdatetime

Complaint

What the customer told us.

  • userId, txnId?string
  • channelCHAT · VOICE
  • text, languagestring
  • audioUrl?Storage URL
  • incidentId?link

Incident

One shared root cause.

  • title, rootCausestring
  • evidencejson
  • confidence0–1
  • impactedUsers, moneyStuckint
  • statusOPEN · APPROVED · RESOLVED

Action

Something the agent wants to do.

  • incidentIdlink
  • kindOPS_TICKET · CUSTOMER_MSG · AUTO_REPLY
  • drafttext
  • statusDRAFT · APPROVED · SENT
  • approvedBystring

What shows up on the customer's phone.

  • userId, incidentIdlink
  • message, languagestring
  • readAtdatetime?

Who did what, and what we learned.

  • actorAGENT · HUMAN

  • preventionRuletext

07 · Team rules

Four things everyone sticks to

One door to the LLM

Every model call goes through lib/llm.ts. Never hardcode a provider.

Human approves every send

Customer messages and tickets wait for Approve, and every action lands in AuditLog.

Mock data only

No real customer data. Mask phone and account numbers on screen.

Demo first

We have about 8 hours and a 2-minute demo. If a feature isn't in the flow above, skip it.
